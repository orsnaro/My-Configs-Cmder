# CachyOS Hyprland — permanent Pleamar / Vitreus desktop

Exported from the live session on **2026-10-20** after the permanent cutover and the settings/calendar polish.
Pleamar **0.4.18** · Vitreus scene (customized) · Hyprland **0.56.2** · CachyOS.

This is a **curated public export**: source and configuration only. It contains no
credentials, private trial checkpoints, notification history, or private snapshot
payloads. The full pre-Pleamar rollback pair lives outside this folder; see
[Restore and rollback](#restore-and-rollback).

## Installed on the live machine

| What | Where |
| --- | --- |
| Shell source | `~/.config/pleamar/shells/vitreus` |
| Pinned binary | `~/.local/bin/pleamar` (0.4.18, sha256 `e446748e072da1a4c799253ec6f63ea22b68f942a00f1ed5ac708a1e2fbd4cf5`) |
| GPU/wayland-start wrapper | `~/.local/bin/pleamar-start` |

| Runtime settings | `~/.local/share/pleamar/vitreus` |

The unit is deliberately **not enabled** with a `WantedBy=` target. It is started by
Hyprland's autostart hook, so it comes back with the graphical session.

## Behaviour that is intentional

- **Main bar:** on DP-2, `bar-position.json` = `ftop`; the frame is **on**
  (`bar_frame=true`, `bar_anchor=top`). The latest saved user setting is solid
  obsidian (`glass_obs=true`); this checkpoint preserves it rather than resetting
  the glass settings.
- **Compact side bars:** 32px strips on DP-1 and HDMI-A-2, with workspace
  icons/labels, clock, **RAM usage**, and scroll-volume/right-click mute. RAM
  reuses the main bar's readout; no new collector or polling. Typography, palette,
  workspace `pop` spring/halo and shared theme transitions follow the main bar.
  Materials now follow its glass/solid controls (opacity, lens, manual/auto frost,
  refraction, dispersion and rim), obsidian blur, Retro plastic and UwU gradient;
  Cyber gets a compact local outline. This supersedes the earlier flat-only design.
  Full-screen drawer/wave passes are not duplicated on the side strips.
  **DP-1 is 6px down**, with 38px total reserved space; HDMI-A-2 remains at the
  top with 32px reserved. Both keep their width. A strip closes if the full
  bar moves to that output, or the full bar uses All/fallback-All. Side input
  acceptance remains user-driven; live layer sizes and ownership are verified.
- **Order:** the custom right run is Power — Settings — Language — Mic/Volume;
  notifications sit just right of the clock; tray dividers only bookend the
  tray/background apps.
- **Bar editor:** the live bar is **Frame** (`bar_frame=true`, `bar_tm=1`), so its
  pieces keep the fixed anchors and the 76 px top / 23 px other-edge gaps. The
  Settings > Bar editor is intentionally faded and says the Frame layout cannot
  be adjusted; this was the user's explicit choice on 2026-10-20. The custom
  right run and the existing order were not changed.
- **Google Calendar (read-only):** the calendar panel reads the pre-existing
  `~/.config/gcal/cache.json` written by the old statusbar integration. It shows
  Google events with a small calendar glyph, no tick/delete controls, and adds
  their dates to the month dots. The bounded `bin/vitreus-gcal-sync` runs the
  existing read-only `gcal-sync.py` through the existing `.venv` and token once
  on the first calendar open per Pleamar session. No Google Cloud app, token
  copy, event write, task write, or OAuth consent flow was added. A failed sync
  leaves the cached rows in place. The OAuth token and cache live outside this
  export (`~/.config/gcal`, mode 600) and are deliberately not included; on a
  fresh home the calendar falls back to local reminders only.
- **Hyprland persistence:** `hyprland.lua` now loads `vitreus_monitors.lua`,
  `vitreus_hypr.lua`, and `vitreus_colors.lua` at the end. The saved Hyprland
  file was reconciled to the live values first (the stale `rounding = 22` was
  corrected to live `10`), so enabling the loader did not change the current
  look. A display Keep writes `vitreus_monitors.lua`, but no such file was
  copied into the live config during this checkpoint; the first real Keep still
  needs visual confirmation.
- **Toast:** `max(0, screen.height * 0.10 - 110)` — the user's latest upward
  adjustment. At 2560×1440 the extra downward offset is **34 px**.
- **Workspace switch:** active tiles use the same spring as hovered tiles.
- **Volume wheel:** scrolling over the audio icon steps volume by 5%, clamped
  to 0–100%; it uses the existing audio watch, with no added polling.
- **Keys:** bare Meta opens the Pleamar launcher; `Alt+Tab` and `Super+Tab` open
  Pleamar's window picker; `Super+Shift+Space` opens Settings; `Super+L` falls
  back to `hyprlock`. Existing `Super+Space` (keyboard layout) and `Super+B`
  (Brave) are preserved, as are unrelated ML4W binds. **Super+W** toggles the
  existing wallpaper picker; no extra background process is added.
- **Settings safety (live):** the Power-menu Lock now runs the same
  `pidof hyprlock >/dev/null || hyprlock` policy as `Super+L`; About Restart and
  monitor-topology restarts queue `systemctl --user --no-block restart
  pleamar.service` instead of a detached quit/respawn. Topology restarts still
  wait for two changed looks and 1500 ms, recheck the display trial and target
  geometry, and keep one pending request; About adds failure recovery and a
  20 s unlatch. Desktop widget scenes are Hyprland children outside the unit
  cgroup, so a service restart does not relaunch them (the plan excluded
  `pkill`); a manual, non-unit shell keeps running when it requests a restart.
  No live lock or restart was pressed to verify this batch.
- **Open apps:** there is no dock/taskbar piece. The Player drawer (click the
  window-title piece) lists running windows (up to 12; six rows visible), and
  `Alt+Tab`/`Super+Tab` opens the Overview with workspace window cards. The Desk
  tabs (Pad/Shelf/Clip/Focus/Term/Ask) are not an app dock.
- **Wallpaper collection:** `wallpaper-dir.json` points to
  `~/.config/ml4w/wallpapers` (68 images at verification). The missing default
  `~/Pictures/Wallpapers` caused the previously empty picker. Vitreus slideshow
  is **off**, as approved; ML4W's independent automation is unchanged. The current
  wallpaper was not changed during correction.
- **Focus follows the mouse:** `activewindow` closes an open bar drawer or
  launcher; `focusedmon`/`focusedmonv2` also close it when moving to another
  monitor, including an empty one. The existing 400 ms opening grace remains.
  Monitor changes also dismiss the wallpaper picker, overview and dashboard.
  Ordinary same-monitor window focus keeps their previous behavior. No extra
  catcher surfaces or polling were added. The user verified both side monitors.
- **Walker/Elephant:** not running and not autostarted by this profile. Their
  old startup commands return only when the pre-Pleamar configuration is restored.
- **Monitor changes:** the Bar selector now queues a `pleamar.service` restart
  rather than quitting and launching a helper that systemd kills. Fixture-tested;
  an actual selector change still needs user acceptance. Other legacy restart
  paths are not covered by this fix. The legacy full-bar All mode is still capped
  at two copies; the approved full-main/lite-sides layout covers all three outputs.
- **GPU:** the compositor renders on the AMD RX 6600 XT (`renderD129`, RADV).
  `pleamar-start` exports
  `VK_DRIVER_FILES=/usr/share/vulkan/icd.d/radeon_icd.json` (plus `DRI_PRIME=1`).
  Without that, Vulkan enumerated the Intel UHD 730 (`renderD128`) first, and
  every shell frame crossed GPUs. Measured before: mean **22–49 ms**, p99
  **≈130 ms**, bursts of 100–139 ms. After: mean **5.9 ms**, p99 **7–9 ms**,
  **0 slow frames** in the sampled windows.

## Restore the permanent setup on a fresh home

```bash
# 0. Install the pinned Pleamar 0.4.18 binary at ~/.local/bin/pleamar first.

# 1. Shell source
mkdir -p ~/.config/pleamar/shells
cp -a source/vitreus ~/.config/pleamar/shells/vitreus

# 2. Hyprland files (back up the current ones first)
mkdir -p ~/.config/hypr/conf
cp -a config/hypr/hypr_vitreus.lua config/hypr/hyprland.lua config/hypr/custom.lua ~/.config/hypr/
cp -a config/hypr/conf/autostart.lua ~/.config/hypr/conf/autostart.lua

# 3. Service + wrapper
mkdir -p ~/.config/systemd/user ~/.local/bin
cp -a systemd/pleamar.service ~/.config/systemd/user/pleamar.service
cp -a bin/pleamar-start ~/.local/bin/pleamar-start
chmod 755 ~/.local/bin/pleamar-start

# 4. Runtime settings (merge; do not delete the rest of the directory)
mkdir -p ~/.local/share/pleamar/vitreus
cp -a data/bar-position.json data/glass.json data/bar-layout.json data/bar.json ~/.local/share/pleamar/vitreus/
cp -a data/wallpaper-dir.json data/wallpaper.json ~/.local/share/pleamar/vitreus/
# On another machine, update wallpaper-dir.json to an existing wallpaper folder.

# 5. Load it now
systemctl --user daemon-reload
systemctl --user start pleamar.service
hyprctl reload
```

The helper symlinks (`vitreus-term`, `vitreus-files`, `vitreus-polkit-agent`,
etc.) are created by the shell's installer normally. On this machine they point
into `~/.config/pleamar/shells/vitreus/bin/`; recreate them if a fresh install
needs them:

```bash
for f in ~/.config/pleamar/shells/vitreus/bin/*; do
  ln -sfn "$f" ~/.local/bin/"$(basename "$f")"
done
```

To go back to the ML4W/Quickshell desktop manually:

```bash
systemctl --user stop pleamar.service
systemctl --user unmask swaync.service
# restore ~/.config/hypr/hyprland.lua and ~/.config/hypr/conf/autostart.lua
# from the pre-Pleamar snapshot, then:
hyprctl reload
```

Packages were **not** uninstalled: Waybar, SwayNC, Walker, Quickshell and the
ML4W dock are only closed/masked/not-started. `swaync.service` is persistently
masked on the live machine (it was runtime-masked before; the persistent mask
keeps D-Bus activation from resurrecting it).

## Known startup notes (not regressions)

- The native Vitreus lock scene (`lockscreen/lockscreen.plm`) is **not started**
  in this install: its socket is absent, Settings > Lock screen shows
  `lk_ok=false`, and `Super+L` / the Power-menu Lock use Hyprlock. Starting it
  needs `PLEAMAR_SWAPCHAIN=1` under `vitreus-keep` (pleamar 0.4 otherwise kills
  the lock surface on lock); this is queued, not a regression.

- The six parser naming notes listed above are pre-existing baseline notes.
- A one-time diagnostic `a drawing is cut: it needs 68 px below…` can appear
  while `bar_position` switches the scene from the reserved island layout to
  the frame at startup. It did not repeat after the layout settled.
- Optional tools that are not installed on this machine degrade features but do
  not stop the shell: `wf-recorder`, `cava`, `mpvpaper`, `python-pyte`,
  `ttf-space-mono-nerd`, `iris-colors`.
- Missing `cava` currently produces runtime errors when the visualizer tries to
  start (seen during the 20:07 reload). It is not an error-free optional fallback;
  the shell service remains active. No package installation was performed.
- **Open theme bug:** a Retro/UwU/Cyber preset round trip intermittently leaves
  colors/subcolors from another theme. A synthetic probe reproduces stale
  external-widget palette delivery under reordered command completion, while
  the main-scene palette restores correctly. The affected live surface is not
  confirmed; no theme fix is claimed. Missing Iris is a separate Glass limitation.
- ML4W's wallpaper automation (`ml4w-wallpaper-automation --start`, a
  pre-existing session process) can respawn `swaync-client -rs` subscribers
  when it re-themes. The SwayNC daemon stays masked, so
  `org.freedesktop.Notifications` remains with Pleamar; kill the stray client
  with `pkill -x swaync-client` if it appears. (The executable is not
  uninstalled.)
- Lite-bar code received inline self-review after the independent review agent
  hit a rate limit. A full-volume label overflow was caught and fixed with a
  RED→GREEN regression before deployment; independent review remains unavailable.
